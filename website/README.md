# Verso website

Static download page for Verso, meant for https://verso.akurba.com.

No build step and no dependency: `index.html`, `style.css`, `app.js` and the
icons are served as is.

## Run locally

```bash
python3 -m http.server 4180 --bind 127.0.0.1 --directory website
```

Then open http://127.0.0.1:4180.

## How downloads work

`app.js` asks the GitHub API for the latest release of `arnkoe/verso` and
links each button to the matching asset (`*_x64-setup.exe`, `*_aarch64.dmg`,
`*_x64.dmg`, as produced by `.github/workflows/release.yml`). A new release
therefore shows up on the site without redeploying it. If the API cannot be
reached, every button falls back to the GitHub "latest release" page.

The visitor's system is detected to highlight the right file. Browsers do not
expose a Mac's CPU type, so the page guesses from the GPU name and defaults to
Apple Silicon.

The page is in French and English; the language follows the browser and can be
switched with the FR / EN toggle.

## Deploy

`verso.akurba.com` is a cPanel subdomain on the `akurba` host (SSH alias),
with its document root in `~/projects/verso`, like the other akurba.com
projects. HTTPS uses the `*.akurba.com` certificate (AutoSSL) and HTTP
redirects to HTTPS (cPanel "Force HTTPS Redirect").

To publish a change to the site, from the repository root:

```bash
rsync -rtv --exclude README.md website/ akurba:projects/verso/
```

`-rt` (not `-a`) leaves the folder's permissions alone: like the other
projects it is `750`, group `nobody`. Do not pass `--delete`: the folder also holds files generated by cPanel
(`.htaccess`, `.user.ini`, `php.ini`, `cgi-bin`). New Verso releases do not
need a redeploy.
