# Verso website

Static download page for Verso, meant for https://verso.akurba.com.

No build step: `index.html`, `guide.html`, `style.css`, `app.js`, `guide.js`,
the images and the icons are served as is. The user guide page loads `marked`
and `DOMPurify` from cdnjs (pinned versions with SRI hashes).

## Run locally

```bash
python3 -m http.server 4180 --bind 127.0.0.1 --directory website
```

Then open http://127.0.0.1:4180.

## How downloads work

`app.js` asks the GitHub API for the latest release of `arnkoe/verso` and
links each button to the matching asset (`*_x64-setup.exe`, `*_aarch64.dmg`,
`*_x64.dmg`, as produced by `.github/workflows/release.yml`). A new release
therefore shows up on the site without redeploying it. If the API cannot be
reached, every button falls back to the GitHub "latest release" page.

The visitor's system is detected to highlight the right file. Browsers do not
expose a Mac's CPU type, so the page guesses from the GPU name and defaults to
Apple Silicon.

The page is in French and English; the language follows the browser and can be
switched with the FR / EN toggle.

## How the user guide works

`guide.html` is the user guide. `guide.js` fetches `README.fr.md` or
`README.md` from the `master` branch on `raw.githubusercontent.com`, renders it
with `marked`, sanitizes it with `DOMPurify` and builds the table of contents
from its `##` and `###` headings. Every push to `master` that changes the README
therefore shows up on the site within about 5 minutes (GitHub's cache), without
redeploying it.

Only the text between `<!-- website:start -->` and `<!-- website:end -->` in
each README is shown; the technical part after the end marker is linked to on
GitHub instead. Keep both markers in both READMEs. Without them the page shows
the whole README. Section anchors match GitHub's, so
`guide.html#installer-verso` works like `README.fr.md#installer-verso`. If
GitHub cannot be reached, the page links to the README on GitHub.

## Screenshots

The images in `img/` are captures of the real Verso interface (operator
window in French and English, projection slides). Regenerate them after a
visible change to the app:

```bash
node scripts/website-shots/shoot.mjs
```

The script loads `src/operator.html` and `src/projection.html` in headless
Google Chrome, with `scripts/website-shots/mock-tauri.js` answering in place of
the Rust back end from the bundled songbooks and Bibles, then searches,
selects and projects like an operator. It needs Chrome and `python3`, no npm
dependency.

## Deploy

`verso.akurba.com` is a cPanel subdomain on the `akurba` host (SSH alias),
with its document root in `~/projects/verso`, like the other akurba.com
projects. HTTPS uses the `*.akurba.com` certificate (AutoSSL) and HTTP
redirects to HTTPS (cPanel "Force HTTPS Redirect").

To publish a change to the site, from the repository root:

```bash
rsync -rtv --exclude README.md website/ akurba:projects/verso/
```

`-rt` (not `-a`) leaves the folder's permissions alone: like the other
projects it is `750`, group `nobody`. Do not pass `--delete`: the folder also holds files generated by cPanel
(`.htaccess`, `.user.ini`, `php.ini`, `cgi-bin`). New Verso releases do not
need a redeploy.
